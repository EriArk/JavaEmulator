# Retroid racing checks and screen-size fix, 2026-10-13

Physical Retroid Pocket Classic, Android 14 / Adreno A12. Two more Java M3G
games were driven through ADB on both the candidate and original engines.
This is short gameplay evidence, not full-game, physical-button or audio
acceptance. Games and APKs are not included in the repository.

## Fixed During Testing

PGR's car and city images are 128x128 textures. The preparation heuristic
mistook their dimensions for a phone screen and cropped the menus to 128x128.
It now ignores anonymous power-of-two square images as dimension-only screen
evidence. Explicit size declarations, named title/menu backgrounds and ordinary
portrait images still count. No game-name exception was added.

Four regression cases cover these distinctions, including archive order.
Existing settings are deliberately preserved. For this newly installed research
game only, its bad config was backed up and fresh preparation was run again;
it retained the 240x320 default and produced readable menus and racing gameplay.
The old config remains backed up locally. No production saves were modified.

## Results

| Game / engine | Surface buffers/s | Host updates/s | Surface P95 | Longest presentation interval | Largest window target P95 |
| --- | ---: | ---: | ---: | ---: | ---: |
| DiRT candidate | 16.59 | 16.59 | 66.67 ms | 83.34 ms | 10.67 ms |
| DiRT original | 16.59 | 16.59 | 66.67 ms | 66.69 ms | 11.98 ms |
| PGR candidate | 13.26 | 13.27 | 83.34 ms | 100.003 ms | 15.29 ms |
| PGR original | 13.25 | 13.25 | 83.34 ms | 100.011 ms | 10.10 ms |

Both games reach moving races with cars, textured environments and visible HUD
progression. PGR shows collision sparks and increasing Kudos. Candidate GPU
session logs confirm hardware geometry and texture reuse; PGR also uses the
sprite path. No recovery is reported in these bounded diagnostic logs.

**There is no observed sustained update-rate deficit in these samples.**
These games do not update at 60 FPS on the original either. Surface buffers and
host paint counts are not independently verified unique game frames. The
candidate is not universally faster: its PGR two-second-window median target
times range 3.29-4.61 ms versus 1.97-2.86 ms original. DiRT ranges 6.71-8.07 ms
candidate versus 8.43-10.06 ms original. The target span includes bind/release,
not GPU execution alone; race/camera states are not frame-identical.

DiRT has no >100 ms presentation interval. PGR has two candidate and one original
interval just over that threshold, approximately six display refresh periods;
neither has a host-update gap reaching 90 ms. Do not report zero long intervals
or general speed parity. Short PSS samples and unavailable reliable thermal
data do not establish long-session memory, battery or throttling behavior.

DiRT uses candidate `3e8c2e5a...4a541df` from the preceding shader checkpoint.
PGR uses `ff02377a...b1c9f0f`, rebuilt with only the preparation fix. Renderer
code is unchanged between these APKs. Both original runs use
`e6a0eb0d...f56885f`. Full hashes are retained in the run summaries.

Mophun was intentionally not tested: the local integration renders its own
ARGB framebuffer through Android Canvas, not `javax.microedition.m3g`. Its
performance would not validate this replacement renderer. No private Mophun
source, game archive, new license, release APK or engine switch is published
by this batch. Public release state was not rechecked.
