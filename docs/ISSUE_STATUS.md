# Issue Status and Remaining Work

Reviewed **2026-11-10** against live GitHub issues/comments, release metadata,
local source at `7d5af534`, and the dated evidence linked below.
The public release remains [0.7.0 Beta 2](https://github.com/EriArk/JavaEmulator/releases/tag/v0.7.0-beta.2),
published November 2. This review did not rebuild/install an APK, repeat runtime
tests, re-download release assets or recheck live multiplayer services. Historical
test counts and device results retain their original dates and scope.

An open issue can mean an unresolved defect, unfinished implementation, or missing
acceptance for an already released feature. Original issue descriptions and
comments remain historical evidence; the dated status at the top identifies the
current remainder. Unchecked original checklists do not mean every feature is absent.

## Development Focus

The maintainer approved this **functionality-first order on November 10**:

1. **#49:** multi-phone EKA2L1 selection, a retained queue, cancellation and
   retry of unfinished phones without replacing imported saves.
2. **#40 / #43 / #51:** remaining helper diagnostics, accessible recovery/cancel
   flows and verified Website/Discord actions in Help/About.
3. **#11:** coordinated built-in styles, retaining readable light/dark palettes;
   imported skins are outside this pass.
4. **#33–#37:** existing Java multiplayer lifecycle using a synthetic test app:
   readiness, start, disconnect, return and rejoin. No new Symbian/Mophun adapter.
5. **#29:** an explicit adaptive ARMv7 Java/Mophun target without Symbian.
6. Assemble a candidate, then test real games and devices, including exact-edition
   #52 reproduction and #48 N95 startup/LCD checks.

#50 remains bounded research alongside this work, without arbitrary-resolution
claims. #44 new platforms, #24 replacement Java VM and additional languages stay
deferred. Existing released implementations are not to be rebuilt merely because
historical issue checklists remain unchecked.

Local compilation was explicitly authorized for this session. This is an exception
to the default server workflow, not a change to release signing or publication policy.

## Accepted Transfer Outcome

**#39 is closed for the accepted whole-phone transfer workflow.** The original
reporter [confirmed Beta 2 on November 4](https://github.com/EriArk/JavaEmulator/issues/39#issuecomment-6621282605).
This resolves importing installed games without individual SIS reinstalls through
the complete-phone copy workflow. It does not implement standalone Drive E scanning
or direct mounting. Broader collection migration and coverage remain in #49.

The reconciliation updated all 33 reviewed issues; 32 remain open.

## Maintenance

After an implementation or release, update the affected issue's current summary,
this record, [PROJECT_STATUS](PROJECT_STATUS.md) and [CHANGELOG](../CHANGELOG.md).
Keep original reports/comments and dated checks intact. Close only the evidenced
scope; broader testing is not automatically a new defect, and a passing synthetic
test is not reporter-specific or complete-game acceptance. No private games,
phone data or credentials belong in these records.
