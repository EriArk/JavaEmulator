# 0.8.0 Beta 1 distribution follow-up, November 22

The initial [component review](2026-11-22-platform-distribution.md) used the private 32-platform APK. The following changes are in source and the combined private Retroid build. The unsigned ARMv7 check was a separate build. GitHub Releases still listed v0.7.0-beta.10 on November 22.

## Changes and verification

| Component | Result |
| --- | --- |
| Watara Supervision | Built Potator's console and audio code with Troy Schrapel's MIT vrEmu6502 and an AbyssME CPU/state adapter. The build selects source files from the two pinned trees and omits the restricted M65C02 directory. An isolated CPU test exercised interrupt delivery, decimal mode during IRQ and checkpoint restore. In a 720-frame host run, Challenger Tank and Crystball both produced changing video and nonzero PCM. Challenger Tank loaded the Retroid's original 24,822-byte checkpoint. Replaying 120 frames produced identical final video and serialized bytes. The Retroid's **Load state** action restored the tank on the road. [Build and regression instructions](../../engines/supervision/README.md). |
| Original Thumby | The system picker installs the RP2040 boot ROM and editor UF2. A real import and a malformed-UF2 regression passed on Retroid. Both firmware images were absent by content from the private APK. The new LittleFS WASM was compiled with Emscripten 3.1.68 from revision `1863dc7883d82bd6ca79faa164b65341064d1c16` and an AbyssME adapter. A flash image built with the same API files and test game matched the old image byte for byte. Donut Clicker reopened on Retroid with its saved count of 11. [System-file setup](../../engines/thumby/README.md). |
| WIPI / SKVM | Packaged the embedded NeoDunggeunmo 1.530 font credit and SIL OFL, core notices and a deduplicated license index covering all 187 name/version pairs from the locked Android normal-dependency tree. Compared these notice files with the APK entries. [Notices and generator](../../engines/wipi/README.md). |
| iPhone OS | Verified all 28 guest-library, font and notice files inside the official v0.3.0 Android package against the pinned touchHLE tree. Generated and checked two source archives for the GNU guest libraries using Apple's gcc-5664 and libstdcxx-39 revisions cited by touchHLE. These archives cover the two guest libraries. The complete native/SDL source set and patches must accompany the eventual distribution. [Source preparation](../../engines/iphone/README.md). |
| ARMv7 | Fixed the release lint error in the guest keypad widget. On the release staging checkout plus the widget fix, the unsigned release, production-APK verification and lint completed. The app suite ran 440 JVM tests and dexlib ran 7, with zero failures or skips. Lint still reported warnings. |
| Retroid installation | Updated the existing combined debug application in place. The first in-place update preserved all 104 package directories and six sampled save hashes. The same 104 directories remained after the final update. During the intervening Donut Clicker play check, the game rewrote its three flash sectors. The two Epoch checkpoints, Color save and pre-existing Challenger Tank checkpoint retained their original hashes. Removed the temporary instrumentation APK. The final private APK SHA-256 was `25beb1a4fa74a0e74e3686fbec3219bf7d322503a2da59523db23cc8944fcb0f`. The packaged Watara ELF text section matched the rebuilt core. After the final packaging update with the WIPI notice index, Donut Clicker again displayed its saved count of 11. |

| GP32emu | Which grant and credit apply to the author's GP32 and ARM core at the pinned revision? | [GP32emu #5](https://github.com/gameblabla/gp32emu/issues/5) |

The original model can already use the imported firmware and source-built LittleFS. |
| libretro/MAME | Which grant covers the shared handheld build and the libretro frontend, given the wording of the pinned COPYING and the MAME legal page? | [libretro/mame #585](https://github.com/libretro/mame/issues/585). The compiler dependency files reference 852 files under src. Of those, 812 have BSD-3-Clause headers and 23 lack a short license header. The list includes common code and is not a final link map. |
| Unicorn / QEMU | Is there a later grant or a rights-holder contact for the pre-2012 part of the original QEMU physical memory code? | [Specific request in the existing Unicorn discussion](https://github.com/unicorn-engine/unicorn/issues/2114#issuecomment-7079937318). The ARM build compiles [softmmu/memory.c](https://github.com/unicorn-engine/unicorn/blob/8028ec436f2d9376525352dd38ed9ed6b9f6be10/qemu/softmmu/memory.c). Its notice grants the later-version option only to contributions after January 13, 2012. ARM build objects for this file are present in the MRE, Pocket PC and Gizmondo build trees. |
| Handyplay | Would the author also offer their MRE code under GPLv2-or-later for a standalone core with Unicorn, or do they have another ARM backend? | [Request on the licensing commit](https://github.com/mohamedahmed166e/my-mre-emulator/commit/b1430bb49c79a0642343aad51912455ab9862b69#commitcomment-211289984). This concerns the author's MRE code only. |

The requests are pending. A standalone MRE option would require implementation and verification of its interface to the app. Pocket PC and Gizmondo also need a compatible route for their Unicorn builds. A public ARM64 package still requires a final component and corresponding-source match, assembly, signing and upgrade checks.
