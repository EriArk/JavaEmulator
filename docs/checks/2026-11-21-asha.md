# Nokia Asha and Series 40 full-touch games · November 21, 2026

The private combined ARM64 debug build extends the existing Java ME platform. Open a MIDP JAR or JAD through Java ME as usual. No Nokia firmware is required. Maintainers can add `-PashaProbe=true` to a debug build. The repository contains the integration source and device evidence. No public APK was produced.

## Playing a gesture game

Touch the game image directly. In **Game menu → Controls**, enable **Nokia gestures: D-pad flicks, OK taps or holds** to play with the existing physical mappings or on-screen keypad. Direction keys flick from the middle of the canvas. OK taps the center, and holding OK produces a long press. Use direct touch to choose a menu item by its position. The setting belongs to the game and defaults to off.

The **Nokia Asha 311 (S40 full touch)** phone preset supplies a full-touch keyboard identity. Automatic setup looks for an explicit 311 model in target metadata or the source filename. On a fresh profile it can use the handset's 240 × 400 canvas when the game gives no dimensions. Fresh profiles honor the Nokia portrait/landscape manifest hint. Games keep their own resolution, input, graphics and save data.

## Retroid Pocket Classic, Android 14

- **TouchMare 1.3, JJR.** Built the author's unmodified MIDlet source and resources using Eclipse ECJ and MicroEmulator CLDC/MIDP compile-time APIs. The game package contains only its classes and assets. On the previous Retroid build startup failed with a missing Nokia gesture class. After implementing gestures, tapping Start exposed a second failure when the first alien ship was created. CLDC lets games define `resume()` on a Thread subclass, while Android reserves that method. The compatibility build resolves the conflicting guest class family and its callers in private executable cache. The original JAR, library identity and RMS are retained.
- During repeated firing, an alien or projectile could disappear while MIDP LayerManager was painting. Retroid reported a null layer in the paint loop. The renderer now takes one stable drawing order per frame and lets game threads change the next frame without holding a lock during guest drawing. A regression test replaces the layers from a second thread during a paint callback.
- Direct touch opened the guest menu on a stationary long press, started a battle, fired and moved the ship with a horizontal flick. Injected Xbox controller A and hat events started the game, fired and moved the ship. Holding A opened the same guest menu. Tapping the on-screen OK key reduced ammunition from 149 to 148. The final build reached Game Over again after 205 rapid keypad taps, without another crash. After saving a per-game B → OK binding and cold-starting the app, an injected B press started another round and a second B press fired (150 to 149 ammunition). The saved keypad and smooth graphics settings survived the restart.
- An Android system-output capture during the title/menu sequence contained 22,486 nonzero mono samples out of 561,152, with peak magnitude 10,550. A second capture during battle and repeated firing contained 34,855 nonzero samples out of 466,944. Physical controller events were injected on the connected device. Original Nokia hardware and hand-operated controller play were not tested.
- **Bounce Tales 1.15, Nokia.** Opened this existing Series 40 game from the Java ME library, started a new game and moved using the controller input path. The first level showed its timer and objective.
- The game created its `TMareHiScore` RMS files. The observed round ended with score zero. The two regression fixtures for executable preparation covered an indirect Thread subclass, interface dispatch, another implementor, a colliding method name and an ordinary unaffected archive.

The final in-place install preserved 9,019 inventoried files and all 82 catalog rows. All 43 selected Android instrumentation tests and both host JVM executable-preparation tests passed.

## API coverage and next cases

| Area | Coverage |
| --- | --- |
| Canvas graphics and softkeys | The existing MIDP Canvas, GameCanvas, Nokia FullCanvas, DirectGraphics, softkeys and controller profiles remain the entry points. |
| Nokia gestures | Per-Canvas listener and bounded zones, tap, held and repeated long press, drag, drop, flick and recognition boundaries. Pinch and double-tap report unsupported. |
| Input and overlays | The ordinary Java pointer path delivers guest coordinates after game-area transforms. The shared emulator keypad and mapping editor are available. Nokia TextEditor and VirtualKeyboard commands are separate guest APIs still to implement. |
| Sensors and orientation | The Java engine already exposes a JSR-256 accelerometer. This session did not exercise physical tilt or model-specific sensor calibration. |
| Asha Software Platform | Asha 501 and later keyboard identity, editing and additional screen behavior need separate coverage. Summeli's GPLv2 Bubblet port is an available full-touch fixture for that work. |
