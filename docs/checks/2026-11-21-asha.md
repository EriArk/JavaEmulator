# Nokia Asha and Series 40 full-touch games · November 21, 2026

The private combined ARM64 debug build extends the existing Java ME platform. Open a MIDP JAR or JAD through Java ME as usual. No Nokia firmware is required. Maintainers can add `-PashaProbe=true` to a debug build. The repository contains the integration source and device evidence. No public APK was produced.

## Playing a gesture game

Touch the game image directly. In **Game menu → Controls**, enable **Nokia gestures: D-pad flicks, OK taps or holds** to play with the existing physical mappings or on-screen keypad. Direction keys flick from the middle of the canvas. OK taps the center, and holding OK produces a long press. Use direct touch to choose a menu item by its position. The setting belongs to the game and defaults to off.

The **Nokia Asha 311 (S40 full touch)** phone preset supplies a full-touch keyboard identity. Automatic setup looks for an explicit 311 model in target metadata or the source filename. On a fresh profile it can use the handset's 240 × 400 canvas when the game gives no dimensions. Fresh profiles honor the Nokia portrait/landscape manifest hint. Games keep their own resolution, input, graphics and save data.

The renderer now takes one stable drawing order per frame and lets game threads change the next frame without holding a lock during guest drawing. A regression test replaces the layers from a second thread during a paint callback.

Injected Xbox controller A and hat events started the game, fired and moved the ship. Holding A opened the same guest menu. Tapping the on-screen OK key reduced ammunition from 149 to 148. The final build reached Game Over again after 205 rapid keypad taps, without another crash. After saving a per-game B → OK binding and cold-starting the app, an injected B press started another round and a second B press fired (150 to 149 ammunition). The saved keypad and smooth graphics settings survived the restart.
- An Android system-output capture during the title/menu sequence contained 22,486 nonzero mono samples out of 561,152, with peak magnitude 10,550. A second capture during battle and repeated firing contained 34,855 nonzero samples out of 466,944. Physical controller events were injected on the connected device. Original Nokia hardware and hand-operated controller play were not tested.
- **Bounce Tales 1.15, Nokia.** Opened this existing Series 40 game from the Java ME library, started a new game and moved using the controller input path. The first level showed its timer and objective.
- The game created its `TMareHiScore` RMS files. The observed round ended with score zero. The two regression fixtures for executable preparation covered an indirect Thread subclass, interface dispatch, another implementor, a colliding method name and an ordinary unaffected archive.

## Asha 501 and Bubblet 1.0.5

The optional Asha 501 preset supplies a 240 × 320 default canvas and a single hardware Back key (`OnekeyBack`). An explicit 501 target in metadata or the source filename selects it during initial preparation. The phone preset can also be selected per game. Existing Nokia 6233 profiles now provide the numeric keypad identity when the game queries it.

Asha Back dispatches the active MIDP screen’s highest-priority `BACK` command. The game-menu handle remains available. In the host’s **More** menu, a full-touch Nokia game can offer a temporary phone keypad when the shared on-screen controls are hidden. A guest can suppress that command with `VirtualKeyboard.hideOpenKeypadCommand(true)`. The user's Controls setting remains independent. Guest softkey popups now keep the MIDlet running. Previously, dismissing one could call the game's startup callback and immediately replace the selected screen.

- Built Bubblet 1.0.5 from the author's unmodified GPLv2 sources and assets. Only guest classes and artwork enter the test JAR. JSR-211 signatures were used at compile time for the optional Asha 1.1 sharing path. The 1.0 handset profile does not expose that action. The JAR was named `Bubblet-Nokia501.jar` for the model-detection check.

The score of 478 survived cold starts, the in-place APK upgrade and opening the same JAR as `Bubblet.jar` with **Use Bubblet**. Short Back returned to the board. The on-screen left softkey and a remapped controller B opened the guest menu. The B binding, on-screen keypad and smooth graphics filter persisted after a cold start. Controller events were injected through the device input path.
- The game contains no audio assets or playback calls. A six-second system output capture during play contained 274,432 silent mono samples. Bounce Tales 1.15 also entered its first level on the final build.
- The final install preserved 9,028 inventoried files and all 83 catalog rows. All 45 selected Android tests passed. The games and APK remain on the test device. At this checkpoint, pinch, double-tap, guest text editing and physical sensor calibration still needed coverage.

## Double-tap and pinch

The private combined build recognizes nearby successive taps and two-finger pinches in the existing Nokia gesture zones. Games registered only for taps receive a single tap immediately. When a zone requests both tap types, it receives one double-tap for a close pair or a single tap after the pairing window. With Nokia gesture controls enabled, two quick OK presses can also produce a double-tap. Keypad and touchscreen taps are tracked independently.

Pinch events use guest canvas pixels and report the starting distance, current distance, center and changes since the previous report. Lifting either finger lets the remaining finger drag. Android cancellation, hiding the canvas and changing image rotation clear the pending contact sequence.

On Retroid Classic, an original diagnostic MIDlet registered for the full Nokia gesture mask. Injected screen taps produced one single and one double. Input through two slots of the Retroid touchscreen produced eleven pinch updates. The MIDlet displayed a distance of 53 pixels at the start, 113 when spread and 42 when brought together. The reader ran in a temporary guest profile outside the user's catalog. [On-device readings](2026-11-21-asha-gestures.png).

TouchMare 1.3, which requests tap, flick and long press, entered battle from a direct tap. The on-screen OK button and the saved controller B mapping fired shots, reducing ammunition from 150 to 148. A horizontal flick moved the ship. New gesture behavior was measured with the diagnostic MIDlet. This pass used injected input on the Retroid and did not repeat audio or complete-game checks. [Nokia gesture interface reference](https://nikita36078.github.io/J2ME_Docs/docs/nokiaapi2/com/nokia/mid/ui/gestures/GestureEvent.html).

The final in-place install preserved all 83 catalog entries and 9,028 inventoried files. The 52 focused device tests and the separate MIDlet run passed.

## Canvas text entry

The optional Asha debug build supports Nokia `TextEditor` fields parented to a MIDP Canvas. The guest sets bounds in canvas pixels and controls the editor's focus and visibility. Android provides the editable field and keyboard. Text, cursor and selection positions use Unicode code points at the guest boundary. Guest code can set text limits, colors, font, multiline mode and input constraints and listen for user edits.

On Retroid Classic, a diagnostic MIDlet on the Asha 501 profile opened the Android keyboard from its high-score screen. Injected key events entered “Asha” and an injected tap on Gboard's X key completed “Ashax”. Tapping the guest's save command dismissed the keyboard. The next tap reached the canvas, which displayed “Playing as Ashax” and counted five content-change notifications. [Retroid screenshots](2026-11-21-asha-editor.png).

The [PluotSorbet TextEditor MIDlet](https://github.com/mozilla/pluotsorbet/blob/46ee3e78a4fd9c3f09026cc5cbdcf76e94b7a398/tests/midlets/texteditor/TextEditorMIDlet.java) was compiled from its unmodified application source with a local test utility for the optional emoji command. Its three editors appeared together. The first accepted an extra Z and wrapped the line, the password stayed masked and the guest's separate canvas readout displayed “AAAAAZ” after dismissing the keyboard and tapping the game. Neither diagnostic added a library row.

All 96 focused device tests passed, including native input-connection commits, Unicode capacity and caret behavior, canvas recreation, detach, existing gestures and canvas lifecycle checks. The combined build was installed over the existing Retroid app. Its 83 catalog rows and 9,028 inventoried files matched before and after. None of the 1,169 JARs scanned from the local game archive referenced `com/nokia/mid/ui/TextEditor`. Game-specific text entry, audio and hand-operated controller input were not verified in this pass. This text-entry check did not cover specialty Nokia input indicators, CustomItem parents or keyboard visibility notifications. [Nokia TextEditor API](https://nikita36078.github.io/J2ME_Docs/docs/nokiaapi2/com/nokia/mid/ui/TextEditor.html).

## System keyboard visibility

Asha MIDlets can register a `KeyboardVisibilityListener` to receive Android keyboard show and hide events on the guest event thread. `VirtualKeyboard` reports the part of the game image covered by the docked keyboard in MIDP pixels. The mapping uses the actual position, scale and rotation of the game image. A game can also call `suppressSizeChanged(true)` to prevent an IME-driven resize. On this Retroid the canvas stayed 240 × 320, and toggling suppression off allowed Android to resize the window again.

On Retroid Classic (Android 14), a diagnostic Asha 501 MIDlet displayed a 240 × 320 canvas. Gboard covered the bottom 141 guest pixels, starting at y = 179. The MIDlet used that measurement to move **Save name** above Gboard. Tapping it saved “Lara” and dismissed the keyboard. Android Back also delivered a hide notification. Removing the listener stopped notifications through another open/close cycle and re-registering resumed delivery. Both notification methods received the system keyboard category. [Before and after saving](2026-11-21-asha-keyboard.png).

The device suite covered 58 cases across keyboard geometry, Nokia text editing, gestures and the canvas lifecycle. The diagnostic MIDlet ran separately in a temporary profile. The in-place update matched all 83 catalog rows and 9,028 inventoried files. None of the 1,169 scanned JARs in the local game archive referenced the visibility listener. This pass used injected input and a docked Android keyboard. Floating IMEs, sound, physical button presses and Nokia's separate custom game keypad were outside the device check. [Nokia VirtualKeyboard API](https://nikita36078.github.io/J2ME_Docs/docs/nokiaapi2/com/nokia/mid/ui/VirtualKeyboard.html).

| Area | Coverage |
| --- | --- |
| Canvas graphics and softkeys | The existing MIDP Canvas, GameCanvas, Nokia FullCanvas, DirectGraphics, softkeys and controller profiles remain the entry points. |
| Nokia gestures | Per-Canvas listener and bounded zones, tap, held and repeated long press, drag, drop, flick, double-tap, pinch with distance and center deltas, and recognition boundaries. |
| Input and overlays | The ordinary Java pointer path delivers guest coordinates after game-area transforms. The shared emulator keypad and mapping editor are available. Guest-controlled custom keypads and specialty text indicators remain open. |
