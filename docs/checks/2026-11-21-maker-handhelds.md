# Maker handheld feasibility review, 2026-11-21

This review covers all eleven ecosystems in [#113](https://github.com/EriArk/JavaEmulator/issues/113) and the PicoSystem firmware target in [#112](https://github.com/EriArk/JavaEmulator/issues/112). Nine have a concrete adapter or runtime worth scheduling. Three have a game library but still need an engine or a reuse decision. The [integration queue](../PLATFORM_ISSUES.md#integration-queue-easiest-first) places them alongside the older handhelds.

## Checks that changed the order

| Target and input | What ran | Result and remaining work |
| --- | --- | --- |
| Arduboy, **ArduGolf** (Intel HEX) | Retroid Pocket Classic, Android 14. A standalone NDK frontend loaded the Android ARM64 Ardens libretro core reporting v0.25.12. Two fresh runs of 600 frames, one idle and one pressing A for ten frames every fifty from frame 120. | Both returned 600 frames at 128 × 64. At frame 599 the framebuffer hashes were `a332767e` idle and `86cbde0f` with A. Only the input run reported writing a save. Both audio buffers contained silence. |
| Arduboy FX, **Dazzle Dash** (packaged HEX, FX data and save seed) | Same device and frontend, original `.arduboy` archive, 600 frames with the same A sequence. | 600 video frames and 36,025 nonzero stereo sample pairs out of 499,948. These were core callbacks. Remaining work includes playback through the Android mixer, testing the shared touch deck and a physical pad, and restoring a game save after cold launch. |
| Gamebuino Classic, **Bomber.hex** | Standalone Simbuino4Web player from catalog revision `9088327dd016` in local desktop Chromium. Compared two runs with the same timing, one holding A for twelve emulated frames. | Both reached the same 84 × 48 screen with 1,137 dark pixels before input. After twelve frames plus 45 further frames, the idle run still had 1,137 dark pixels and the input run had 412. Android WebView pacing, audio activation, persistent EEPROM and writable SD need device checks. |
| Pokitto, **MicroCity.bin** and **GalaxyFighters.pop** | Upstream PokittoEmu v1.0.5, Linux x86-64 with SDL dummy output. Used the emulator's frame-triggered PNG capture. | Both loaders produced the Pokitto startup screen and hardware loader countdown. A successful boot capture alone does not establish gameplay, sound or writable SD on Android. |
| PicoPad / picogame, **PicoRacer** | Desktop Python headless simulator at `11c4a657f649`, original game directory, 150 frames. | The simulator completed the run and produced a frame capture. Its documented desktop audio path is silent. An Android guest runtime and audio implementation are separate work. |

The Retroid test ran under a temporary shell directory, outside the installed app. The tested core SHA-256 was `806be223cddbc72234d513468f8bf0dc9ab8dc6b5926cda0dab9cfeba65aa38b`. The ArduGolf input SHA-256 was `490762efcb30f85473443d91c16d22174f4cfab66371ad68e27c83dd1a9fd879`, and Dazzle Dash was `a4201ed9820cae389c8d7a4dd1338b90a1def6e90bc833be9eedce3b33318358`. Rebuild from reviewed sources for the app. These checks did not install a platform tab or publish an APK. [Core implementation](https://github.com/tiberiusbrown/Ardens/tree/e811cc6be72c/src/libretro_core) · [Test games](https://github.com/tiberiusbrown/Ardens/tree/e811cc6be72c/tests) · [Android core distribution](https://buildbot.libretro.com/nightly/android/latest/arm64-v8a/) · [Bomber fixture](https://github.com/joyrider3774/gamebuino_classic_games_compiled/blob/9088327dd016/games/Bomber.hex) · [MicroCity](https://github.com/jhhoward/MicroCity-Pokitto) · [Galaxy Fighter](https://github.com/Press-Play-On-Tape/GalaxyFighter_Pokitto) · [PicoRacer](https://github.com/MakerClassCZ/picogame/tree/11c4a657f649/games/picoracer).

## Candidates in implementation order

| Platform | Game and source evidence | AbyssME integration and first unresolved question |
| --- | --- | --- |
| **Arduboy / FX** | ArduGolf, ArduChess, ArduRogue, Dazzle Dash and Return of the Ardu. Ardens supplies a dedicated libretro target, MIT core and dependency inventory. [Ardens](https://github.com/tiberiusbrown/Ardens/tree/e811cc6be72c) · [Game and benchmark packages](https://github.com/tiberiusbrown/Ardens/tree/e811cc6be72c/bench) | Start with the existing [handheld frontend](../../engines/handheld/native/frontend.h). Wire video format, actual sample rate, D-pad and A/B. Import HEX and packaged FX games, keep matching flash data with each game and persist EEPROM/FX changes. Inspect licenses for the selected target, including embedded bootloader assets. |
| **Gamebuino Classic** | The recovered catalog has 159 game entries, including Bomber, BlocksBuino, B-Rally, Aimbuino and Artillery. The browser core provides the ATmega328, buttons, LCD, speaker and SD interface. [Catalog and component credits](https://github.com/joyrider3774/gamebuino_classic_games_compiled) · [Original MIT Simbuino source](https://github.com/Myndale/Simbuino/tree/master/src/Simbuino4Web) | Wrap the local JS player with shared input and a directory for each game's EEPROM and SD assets. Map A/B/C. The platform selected at import resolves ambiguous Intel HEX shared with Arduboy. Use games individually according to their terms. The alternative [gbsim](https://github.com/33d/gbsim) lists sound, SD and EEPROM as missing. |
| **Pokitto** | MicroCity, Galaxy Fighter, Road Trip, Karateka and Dark Ritual have author repositories. PokittoEmu accepts both binary and POP packages and supplies an SD image interface. [MIT engine](https://github.com/felipemanga/PokittoEmu) · [MicroCity](https://github.com/jhhoward/MicroCity-Pokitto) · [Game author's catalog](https://github.com/orgs/Press-Play-On-Tape/repositories?q=Pokitto) | Isolate the native CPU/peripherals from the SDL window, connect PCM and D-pad/A/B/C, preserve POP art and adjacent SD assets. Test a game that reads data from SD, writes a save and resumes. Check the bundled filesystem implementation separately from the engine license. |
| **Original Thumby** | AlienInvasion, Annelid, AstroJumper, 8bdungeon and 4Connect are in the device catalog. The official editor ships a board emulator, firmware, RP2040 boot ROM and littlefs support. [Game catalog](https://github.com/TinyCircuits/TinyCircuits-Thumby-Games) · [GPLv3 editor and embedded components](https://github.com/TinyCircuits/TinyCircuits-Thumby-Code-Editor/tree/5b3710cc100a) | Package the local emulator without the editor. Install each game's MicroPython directory and assets on its guest filesystem. Verify frame timing, buzzer, D-pad/A/B and writes. Review the included firmware and boot ROM separately. |
| **Thumby Color** | BustAThumb, Chess, ComboPool, FroggyRoad and Monstra use the Color catalog. Tiny Game Engine has Linux/SDL and WASM targets and four audio channels. [GPLv3 runtime and platform drivers](https://github.com/TinyCircuits/TinyCircuits-Tiny-Game-Engine/tree/670b938df407) · [Color games](https://github.com/TinyCircuits/TinyCircuits-Thumby-Color-Games) | Reuse the original Thumby's directory import and save handling. Embed the Color MicroPython fork and its own engine API. Start with FroggyRoad, then test a game with streamed assets and audio. |
| **ESPboy Little Game Engine** | FourInaRow, NinjaEscape, TankCity, SpaceFighter and WormBlast are device games. The SDK contains a browser VM, compiler and sound implementation. [BSD-3-Clause SDK](https://github.com/corax89/game_engine_for_esp8266_with_compiler) · [GPLv3 device implementation and game packages](https://github.com/ESPboy-edu/ESPboy_little_game_engine/tree/3adf0c875f99/data) | Port the VM input/display/sound interface into the local web host. Start with NinjaEscape and verify its package header, button mapping and persistent data. The scope is LGE bytecode. Arbitrary ESP8266 firmware needs a different machine model. |
| **MakeCode Arcade** | Bunny Hop, Cat Jumper, Catch, Duck and Space Destroyer are playable project examples. [MIT target, third-party notices and games](https://github.com/microsoft/pxt-arcade/tree/0642e6159d3f) · [Space Destroyer](https://github.com/microsoft/pxt-arcade/blob/master/docs/blocks-games/space-destroyer.md) | One ecosystem for Meowbit, PyGamer and PyBadge. Start with an offline project using stock extensions. Establish a reproducible project-to-simulator build and local dependencies, then map the controller, audio and settings storage. Board-specific UF2 support is a separate path. |
| **PewPew / Lite** | Snake, Frog, Othello, Boulder and Sokoban have individual source repositories. The desktop reference implements the small Python display/input API using pygame. [Game author organization](https://github.com/pypewpew) · [Snake](https://github.com/pypewpew/game-snake) · [Reference and CC BY-SA 4.0 notice](https://github.com/pypewpew/pew-pygame) | After the Python runtime work, implement the 8 × 8 matrix, palette, keys and tick timing for the original device profiles. Start with Snake. Review the reference code and individual game licenses if redistributing any part. |
| **PicoPad / picogame** | PicoRacer, PicoTris, PicoWing, BangBang and SQuest have complete source and assets. [MIT project, device modules and simulator](https://github.com/MakerClassCZ/picogame/tree/11c4a657f649) | Reuse the Python packaging work. Match the CircuitPython/native picogame API, scaling and buttons, then implement sound and persistent storage. Accept games targeting this runtime. General PicoPad UF2 firmware has different requirements. |

## Candidates with an unresolved engine choice

| Platform | Games and outstanding decision |
| --- | --- |
| **Pimoroni PicoSystem** | PiKart's author supplies a native UF2 with saves, sound and A/B/X/Y controls. The SDK's Snake, Invader, Match 3 and Gate Keeper bring the sample to five distinct titles. DERP's SDL host implements buttons/audio and approximates the display via PIO hooks. The inspected revision has no identified project license. Its README explains how to obtain the boot ROM from Raspberry Pi's release. The MIT pico-emu alternative still needs a PicoSystem board/display/audio adapter. Use native PiKart, Invader and Match 3 to compare the board paths. Android gameplay and the engine choice remain open. [PiKart firmware](https://rigare.itch.io/pikart) · [SDK Snake](https://github.com/pimoroni/picosystem/tree/main/examples/snake) · [Invader UF2](https://github.com/lummi01/Picosystem-Invader) · [Match 3 firmware](https://github.com/deckerego/picosystem-demo/releases/tag/1.0.0) · [Gate Keeper release](https://github.com/Blackhawk-TA/GateKeeper/releases/tag/v1.0.1) · [DERP revision](https://github.com/Daft-Freak/DERP/tree/9411555f3b4d) · [pico-emu](https://github.com/danish9661/pico-emulator) · [RP2040 boot ROM sources and terms](https://github.com/raspberrypi/pico-bootrom-rp2040) |
| **Gamebuino META** | The native SDK contains Pong and the author of Gruniożerca META supplies a precompiled binary. gm0 supports META, but its aggregate license is CC BY-NC-SA 4.0. The independent MIT TypeScript implementation models the ATSAMD21 and buttons. Check its coverage of display, SD, DAC and timing with Gruniożerca before committing to a port. A five-game sample for this particular host remains open. [SDK](https://github.com/Gamebuino/Gamebuino-META) · [Game](https://github.com/arhneu/gruniozerca-meta) · [MIT implementation](https://github.com/aoneill01/gamebuino-emulator) · [gm0 terms and provenance](https://github.com/r043v/gm0/blob/main/LICENSE) |
| **Tiny Arcade** | The official SD collection includes ColorMonster, CutieCritters, Hecubus, Flappy Birdz and MicroVektoRoids. Use a native game directory with assets, for example CutieCritters. It runs on TinyScreen+ hardware. A suitable reusable host for this board's display, joystick, audio and SD loader is still unidentified. Reassess with the SAMD21 work for META. [Manufacturer's game files](https://github.com/TinyCircuits/TinyCircuits-Tiny-Arcade-Games/tree/master/Tiny-Arcade-All-Games) · [Device and loader](https://learn.tinycircuits.com/Help/Tiny-Arcade-DIY-Kit_Menu-Update/) |

For every new adapter the remaining device work includes the normal AbyssME library import, shared display settings, touch layout, physical remapping, game saves and backup/restore. All packaged games remain separate from the emulator. The next Arduboy check can use the upstream fixtures without a maintainer-supplied ROM.
