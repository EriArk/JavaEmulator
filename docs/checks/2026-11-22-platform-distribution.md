# Platform distribution review for 0.8.0 Beta 1

The review used the private 32-platform ARM64 APK, build scripts at `1dc0dc86`, pinned source notices and the last public Beta 10 verification. It covers the following release questions. It does not certify every transitive dependency or artwork file. No APK, game or firmware is distributed with this report.

This was the initial audit. The [same-day follow-up](2026-11-22-license-remediation.md) records the replacement CPU, firmware import, rebuilt LittleFS, notices and upstream requests.

| Platform | Evidence from the current integration | Path to a release decision |
| --- | --- | --- |
| Watara Supervision | Potator links `common/m6502/m6502.c`. This file expressly disallows commercial distribution. The APK includes the same M65C02 notice alongside the repository's Unlicense. | Replace the CPU with a compatible 65C02 implementation and retest, or obtain a compatible grant for this file. [Pinned CPU notice](https://github.com/libretro/potator/blob/227c5f6f3ce74d32e9002ce24c1420288559a860/common/m6502/m6502.c) |
| GamePark GP32 | The libretro metadata says BSD-3-Clause/MIT. The pinned tree has specific notices for MAME-derived files, the BDMEmu frontend and the ZIP library. Those notices do not explicitly identify the grant for all the original emulator code linked into the APK. | Map the remaining files to a grant or obtain clarification for the pinned core. User-supplied BIOS and cartridges are a separate matter. [Core at the shipping revision](https://github.com/gameblabla/gp32emu/tree/6e5091f115fb1976f128a9696f59b2e421eb62b0) |
| MRE, Pocket PC and Gizmondo | Each integration uses Unicorn or a fork. Upstream describes Unicorn as GPLv2. Gizmondo's pinned Cargo metadata says GPL-2.0. The Handyplay MRE build links its AGPLv3 core with Unicorn. | Determine whether the linked files allow GPLv3 or another compatible grant and examine the actual binary boundaries. GPLv2-only and GPLv2-or-later have different outcomes. GPLv3 provides for combination with AGPLv3. [Unicorn](https://github.com/unicorn-engine/unicorn/blob/8028ec436f2d9376525352dd38ed9ed6b9f6be10/README.md), [GNU compatibility guidance](https://www.gnu.org/licenses/gpl-faq.en.html#v2v3Compatibility) |
| GameKing, Hartung Game Master and Epoch Game Pocket Computer | The APK includes one shared MAME core. The pinned COPYING specifies GPLv2 for MAME as a whole. Individual drivers have their own grants, including GPL-2.0-or-later and BSD-3-Clause. | Check the linked subset, including the common framework and CPUs, and how the frontend links to it. One review covers three platform tabs. [MAME COPYING](https://github.com/libretro/mame/blob/5f5a07748ce5c239c4118463ce8e6473743d4859/COPYING), [build inputs](../../engines/gameking/build-native.sh) |
| Original Thumby and the shared Color packaging | The installed runtime includes a 16 KiB boot ROM (SHA-256 `410efe8897a7c901e5b666d87787714c9782cf26a0ebf388865e1b0a26075f88`), emulator UF2 and LittleFS WASM from the editor. Raspberry Pi's B2 boot ROM license excludes two floating-point routines. Their headers give a hardware-only grant and identify a separate GPLv2 route. Attribution of the exact editor binary to a source build remains open. | Identify the matching binary/source and grants or replace the ROM. Consider importing the user’s ROM using the existing setup flow. Identify the sources and notices for the UF2 and WASM. Color runs its own engine, but the shared module currently also stages original Thumby assets. Separate them for a Color-only release and check the product-photo-based Color sticker. [Staging](../../engines/thumby/prepare.py), [RP2040 license](https://github.com/raspberrypi/pico-bootrom-rp2040/blob/master/LICENSE.TXT), [math routine](https://github.com/raspberrypi/pico-bootrom-rp2040/blob/master/bootrom/mufplib.S) |
| Early iPhone OS | touchHLE stages modified native code, SDL, guest libraries and fonts. Its guest-library manifest identifies sources and licenses, including GPLv2-or-later GNU libraries. | Match the binaries to sources, patches and notices in the distribution. This is a source-delivery check. [Guest library manifest](https://github.com/touchHLE/touchHLE/blob/8eb3418b3343bc1e3d1a330b55cb1d708a015721/touchHLE_dylibs/README.md) |
| WIPI / SKVM | The byte sequence of the pinned wie `assets/neodgm.ttf` is present in `libwipi_android.so`. Its name table credits Jungtae Kim and Dalgona and identifies SIL OFL 1.1. The APK notice-path search did not find a standalone NeoDunggeunmo notice. | Include the font credit and full OFL terms in release notices and check the Rust dependency inventory. [Font project](https://github.com/neodgm/neodgm), [pinned wie assets](https://github.com/ParkJeongseop/wie/tree/408fdd0ff58964172e7bca499078ca42d876111b/assets) |

Public release configuration, credits and corresponding-source preparation remain separate from device compatibility. Earlier releases cover the established Java ME, Mophun and Symbian/N-Gage versions. Routine notice or source-bundle work alone is not a reason to remove a platform.
